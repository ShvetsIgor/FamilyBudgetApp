# Мобильная версия family.budget — роадмапа

Дата: 2026-07-22. Цель: приложение в App Store и Google Play с пуш-уведомлениями, ИИ-функциями и подпиской премиум. Монетизация: подписка (решение принято, реклама не закладывается). Оценки — в чистых неделях фулл-тайма одного разработчика.

## Выбор пути (решение открыто)

| | Capacitor-обёртка | React Native / Expo |
|---|---|---|
| Срок до сторов | 3–4 недели | 3–4 месяца |
| Код | текущий Next.js как есть | UI заново, TS-домен переносится (~70%) |
| UX | веб внутри нативной оболочки | нативный |
| Ревью Apple | риск придирок к «обёртке» (гайдлайн 4.2); пуши+подписка+ИИ снижают риск | без проблем |
| Долгосрочно | одна кодовая база web+mobile | две базы (web остаётся отдельно) |

Рекомендация: **Capacitor сейчас**, RN — только если Apple завернёт дважды или упрёмся в UX-потолок. План ниже написан под Capacitor; для RN этап 2 заменяется на ~12–16 недель разработки UI, остальные этапы не меняются.

## Этап 0 — фундамент (1 неделя)

- Перевод Firebase на план **Blaze** (Cloud Functions; на текущих объёмах ≈ $0/мес). Снимает главный «Known Gap» проекта.
- Каркас `functions/` в репозитории + деплой в CI.
- **App Check** (reCAPTCHA для web, DeviceCheck/Play Integrity для мобилок) — до выхода в сторы, пока ключи не разошлись по чужим рукам.
- Пререквизит Capacitor: проверить `next build` со `output: 'export'` (приложение полностью клиентское — должно пройти; починить, что упадёт: image-оптимизация, динамические роуты).

## Этап 1 — пуш-уведомления (1–2 недели)

- FCM-токены: регистрация в клиенте, хранение в `users/{uid}/fcmTokens`, чистка мёртвых.
- Cloud Functions-отправители поверх уже существующей pull-логики колокольчика:
  - напоминания о recurring-платежах (за день и в день срока);
  - бюджетные алерты 85%/100% (сейчас считаются на клиенте при запуске — перенести триггер на Function по расписанию);
  - семейная активность (новый участник, крупная общая трата) и инвайты.
- Настройки: тумблеры по типам уведомлений в аккаунте.
- Web-пуши через тот же FCM — бонус почти бесплатно.

## Этап 2 — упаковка в сторы (3–4 недели)

- Capacitor iOS + Android поверх статического экспорта; иконки, сплэши, deep links.
- Нативные плагины: push (этап 1), haptics, status bar, безопасная зона (у приложения мобильный UI основной — адаптация минимальна).
- Аккаунты разработчика: Apple $99/год, Google $25 разово.
- Прохождение ревью. План Б для Apple: подчеркнуть нативные фичи (пуши, подписка, Sign in with Apple*).
- *Sign in with Apple обязателен, раз есть Google-вход — добавить (2–3 дня, Firebase Auth поддерживает).
- E2E: существующие Playwright-сьюты остаются для web; smoke-прогон в симуляторах вручную.

## Этап 3 — ИИ (2–3 недели на v1, дальше итерации)

- Cloud Function-прокси к LLM API (ключ только на сервере; лимиты per-uid — App Check + квота в Function).
- v1: LLM-разбор сообщения в чате («кофе и продукты в Шуферсале 240») → структурированный расход/сплит. Текущий легаси-парсер и детерминированный движок остаются **офлайн-фолбэком** — архитектура «alignment, not replacement» это уже позволяет.
- v2: месячные инсайты («на доставку в этом месяце ×2 больше»), саммари недели в пуше.
- Стоимость: Haiku-класс модели, ≈ $0.01–0.05 на активного пользователя в месяц.
- ИИ-функции — за подпиской (этап 4), лимитированная бесплатная квота для онбординга.

## Этап 4 — подписка премиум (1–2 недели)

- RevenueCat поверх StoreKit/Play Billing (web-версия — без оплаты или Stripe позже).
- Разделение: бесплатно — личный учёт, базовый чат-парсер; премиум — семейный бюджет, ИИ, экспорт, безлимит целей.
- Серверная проверка entitlement в Cloud Function (для ИИ-прокси) + флаг в профиле для UI.

## Итого

| Этап | Срок |
|---|---|
| 0. Blaze + App Check + export | 1 нед |
| 1. Пуши | 1–2 нед |
| 2. Сторы (Capacitor) | 3–4 нед |
| 3. ИИ v1 | 2–3 нед |
| 4. Подписка | 1–2 нед |
| **Всего** | **8–12 недель фулл-тайма** |

Этапы 1 и 2 можно вести параллельно, 3 и 4 — после релиза первой версии в сторы (сторы принимают обновления за дни). Минимальный стор-релиз = этапы 0+1+2 ≈ 5–7 недель.

## Риски

1. **Ревью Apple (гайдлайн 4.2, «просто веб-обёртка»)** — главный риск пути Capacitor. Митигция: пуши, Sign in with Apple, подписка, нативные плагины в первой же сборке. План Б — RN (+3 мес).
2. **Статический экспорт Next.js** — если что-то не экспортируется, правки роутинга до недели.
3. **Расходы Blaze** — на текущих объёмах нулевые, но ИИ-прокси без квот может стать дырой; лимиты per-uid обязательны с первого дня.
4. **Отзыв подписки/refund** — RevenueCat закрывает большую часть краевых случаев из коробки.
5. **Секретность данных** — с пушами содержимое уведомлений не должно раскрывать секретные траты на локскрине (privacy == 'secret' не попадает в пуши вообще).

## Что НЕ делаем (осознанно)

- Свой бэкенд — не нужен ни для одной из целей; Firestore + Functions закрывают всё. Пересмотр — только при уходе с Firebase.
- Реклама (AdMob) — решение: монетизация подпиской.
- Нативные Swift/Kotlin-приложения — неоправданно для соло-разработки.

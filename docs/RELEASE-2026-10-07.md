## Scope

The review in `reviews/2026-10-07/REVIEW.md` records the pre-fix state. This release fixes its financial transaction, auth isolation, invitation, privacy, aggregate caching, and direct-link findings. ## Operations and limitations

- Publish rules with this client; the new `entryOperations` receipts are required by chat writes.
- Aggregates written before this repair are not trusted until recomputed from source entries (`aggregateVersion: 2`). Source money is not rewritten.
- `scripts/repair-entry-privacy.mjs` defaults to read-only and logs counts only. Optional `--apply --backup=/private/path.json` only tightens privacy after rereading the actual categories/goals transactionally. Its backup contains field preimages, not a complete database backup. No apply was needed for this release.
- Before financial data repair, export data from account settings and verify counts/currency totals against source entries in an isolated environment. JSON export is an archive; there is no tested one-click restore UI. Do not advertise it as automatic disaster recovery.
- Firebase remains Spark; quotas and manual support limit initial scale. Launch as a public beta with a limited initial audience. Physical iPhone installation/Siri and recovery from provider outages still require device/operational checks.
- Runtime audit after compatible upgrades has only a moderate transitive uuid/gaxios advisory. The affected v3/v5/v6 caller-supplied-buffer paths are not used by app code. Do not force npm's suggested Firebase downgrade. Development-only glob/braces advisories remain upstream concerns.
- Roll back an app deployment through Vercel to the prior known version. Do not restore the insecure invitation rules to make an old UI work. Re-evaluate older client compatibility before promoting a rollback.
